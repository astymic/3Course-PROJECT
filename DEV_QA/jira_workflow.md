## 2. Колонки (статуси) дошки

```
┌──────────┐    ┌──────────────┐    ┌──────────┐    ┌──────────┐
│  TO DO   │───►│ IN PROGRESS  │───►│  REVIEW  │───►│   DONE   │
│          │    │              │    │          │    │          │
│ Задачі,  │    │ В роботі у  │    │Перевірка │    │Завершено │
│ які      │    │ виконавця    │    │(PM/BA    │    │і прийнято│
│ чекають  │    │              │    │ або QA)  │    │          │
└──────────┘    └──────────────┘    └──────────┘    └──────────┘
```

### Правила переходу:
| З → До | Хто переводить | Умова |
|---|---|---|
| To Do → In Progress | Виконавець | Взяв задачу в роботу |
| In Progress → Review | Виконавець | Артефакт / результат готовий для перевірки |
| Review → Done | PM або QA | Перевірено, прийнято |
| Review → In Progress | PM або QA | Знайдено помилки або зауваження — повернення на доопрацювання |

## 3. Типи тікетів (Issue Types)

| Тип | Опис | Приклад |
|---|---|---|
| **Epic** | Великий блок функціоналу, що охоплює кілька спринтів | «Каталог товарів», «Кошик та замовлення» |
| **Story** | User Story — конкретна функція з точки зору користувача | «Як покупець, я хочу фільтрувати взуття за розміром» |
| **Task** | Технічна або документальна задача | «Налаштувати PostgreSQL на Render» |
| **Bug** | Дефект знайдений під час тестування | «Popup не відкривається на мобільному» |

## 6. Мітки (Labels)

| Label | Колір | Використання |
|---|---|---|
| `must-have` | 🔴 Червоний | Критичний функціонал MVP |
| `should-have` | 🟡 Жовтий | Важливо, але можна відкласти |
| `could-have` | 🟢 Зелений | Бонусний функціонал |
| `phase-2` | 🔵 Синій | Заплановано на Фазу 2 (конструктор) |
| `bug` | ⚫ Чорний | Дефекти |

---

## 7. Правила роботи з дошкою

1. **Кожна Story має Acceptance Criteria** — без них задача не переходить в "Done".
2. **Work In Progress (WIP) ліміт:** максимум 2 задачі в колонці "In Progress" на одного учасника.
3. **Daily Update:** кожен учасник оновлює статус своїх тікетів щодня.
4. **Баги пріоритетніші за нові Story** — якщо є відкритий Bug, він закривається першим.
5. **Sprint Retrospective:** наприкінці кожного спринту команда обговорює що покращити.
